#### Descripción 
What does asm3(0xd3fc4c74,0xdb38982c,0xbd2f0c43) return? Submit the flag as a hexadecimal value (starting with '0x'). NOTE: Your submission for this question will NOT be in the normal flag format. [Source](https://challenge-files.picoctf.net/c_fickle_tempest/d327efde40141f9fb760544210b9d6c6b2352b7ec68bf41bcffc4c2d92915d76/test.S)
#### Solución
El objetivo es **trazar manualmente la ejecución** del ensamblador x86 con tres argumentos.

**Convención de llamada x86 (cdecl) y layout en memoria

En x86 little-endian, los argumentos se almacenan byte por byte:

| Dirección    | Valor  | Pertenece a |
| ------------ | ------ | ----------- |
| `[ebp+0x8]`  | `0x74` | arg1 byte 0 |
| `[ebp+0x9]`  | `0x4c` | arg1 byte 1 |
| `[ebp+0xa]`  | `0xfc` | arg1 byte 2 |
| `[ebp+0xb]`  | `0xd3` | arg1 byte 3 |
| `[ebp+0xc]`  | `0x2c` | arg2 byte 0 |
| `[ebp+0xd]`  | `0x98` | arg2 byte 1 |
| `[ebp+0xe]`  | `0x38` | arg2 byte 2 |
| `[ebp+0xf]`  | `0xdb` | arg2 byte 3 |
| `[ebp+0x10]` | `0x43` | arg3 byte 0 |
| `[ebp+0x11]` | `0x0c` | arg3 byte 1 |
| `[ebp+0x12]` | `0x2f` | arg3 byte 2 |
| `[ebp+0x13]` | `0xbd` | arg3 byte 3 |

**Registro EAX y sus partes

```
EAX (32 bits)
┌────────┬────────┬────┬────┐
│  (high)│  (high)│ AH │ AL │
└────────┴────────┴────┴────┘
                  └───AX───┘
```

| Offset  | Instrucción                                                   | Estado de EAX       |
| ------- | ------------------------------------------------------------- | ------------------- |
| `<+7>`  | `xor eax, eax`                                                | `eax = 0x00000000`  |
| `<+9>`  | `mov ah, [ebp+0x8]` → `0x74`                                  | `eax = 0x00007400`  |
| `<+12>` | `shl ax, 0x10` → ax se desplaza 16 bits, todos los bits salen | `eax = 0x00000000`  |
| `<+16>` | `sub al, [ebp+0xd]` → `0x00 - 0x98` = `0x68` (underflow)      | `eax = 0x00000068`  |
| `<+19>` | `add ah, [ebp+0xc]` → `0x00 + 0x2c` = `0x2c`                  | `eax = 0x00002c68`  |
| `<+22>` | `xor ax, WORD PTR [ebp+0x12]` → `0x2c68 XOR 0xbd2f`           | `eax = 0x00009147`  |
| `<+27>` | `pop ebp`                                                     | —                   |
| `<+28>` | `ret` → retorna `eax`                                         | **return `0x9147`** |

```
  0x2c68 = 0010 1100 0110 1000
  0xbd2f = 1011 1101 0010 1111
  XOR    = 1001 0001 0100 0111 = 0x9147
```
- `2 XOR b` = `0010 XOR 1011` = `1001` = `9` ✓
- `c XOR d` = `1100 XOR 1101` = `0001` = `1` ✓
- `6 XOR 2` = `0110 XOR 0010` = `0100` = `4` ✓
- `8 XOR f` = `1000 XOR 1111` = `0111` = `7` ✓

**Nota sobre `shl ax, 0x10`

`ax` es un registro de 16 bits. Al desplazarlo 16 posiciones a la izquierda, **todos los bits se pierden** y `ax = 0`. Por lo tanto, el `mov ah, 0x74` de `<+9>` queda descartado y no influye en el resultado final.

El WORD leído en `<+22>` viene de `[ebp+0x12]` y `[ebp+0x13]`, que son los bytes 2 y 3 de **arg3** (`0xbd2f0c43`), resultando en `0xbd2f` (little-endian).

**Flag 0x9147

#### Notas

- Este reto introduce operaciones a nivel de **sub-registros** (al, ah, ax) dentro de eax.
- La clave está en entender el layout little-endian de los argumentos en el stack y qué byte exacto apunta cada dirección.
